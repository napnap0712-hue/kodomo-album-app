# おもいでブック Wi-Fi同期（開発中）

## 現在の段階
**接続・ペアリングのテスト専用**。MacBookとWindowsの両方で、Node.jsだけで動作します。
写真・園児情報・アルバムの送受信、保存、自動同期は**まだありません**。6桁のテスト用確認コードで、ブラウザの一時セッションを登録できます。
既存の `index.html` と保存データは変更しません。

## 起動
1. VS Codeで、このリポジトリを開いて開発ブランチに切り替える。
2. Git Pull で最新版を取り込む。
3. ローカルの `npx serve` を使うターミナルとは**別のターミナル**を開く。
4. 次のコマンドを実行。

```sh
node sync-server/server.js
```

MacBook/Windows側で `http://localhost:4318/pair` を開いて確認。
同じWi-Fi上のiPhoneからは、コンソールに表示された
`http://(パソコンのIPアドレス):4318/pair` をSafariで開いて確認。

起動中はターミナルを開いたままにします。停止は Control+C。
`http://localhost:3000` または `http://(IPアドレス):3000` は引き続き既存アプリ用です。
4318番は同期接続・ペアリングテスト専用です。MacBook側のターミナルに表示される6桁の確認コードをiPhoneの画面に入力してください。コードは5分間有効で、接続テスト成功後は使い捨てになります。登録状態はサーバー停止時に消えます。

## セキュリティ注意
- HTTP接続は暗号化されていません。**確認コードも暗号化されずに送信されます**。必ず信頼できるWi-Fiで接続テストだけに使い、写真、園児情報、バックアップファイルや普段使っているパスワードは送らないでください。
- 現段階のサーバーは接続と一時ペアリングのテストしか受け付けません。データ送信APIはありません。
- テストは信頼できる家庭内Wi-Fiでのみ行い、インターネット向けポート公開はしないでください。
- 将来の本番用同期は、端末のペアリング、認証、HTTPS、競合防止、データ保存を別途設計・検証します。
- Windowsで接続できない場合、Windows Defender ファイアウォールやWi-Fiの端末間通信制限を確認してください。

## テスト数字の自動更新（次の段階）
- MacBookまたはWindowsで `http://localhost:4318/demo-value` を開くと、現在のテスト数字が表示されます。
- iPhoneで `/pair` を開き、ペアリング成功後に「数字を1増やす」を押します。
- iPhone画面の数字は3秒ごとに自動更新されます。MacBookでは `/demo-value` を再読み込みして一致を確認できます。
- 送受信するのは数字（0〜99）だけです。サーバー停止で消えます。
- セキュリティ未完成のため本物の園児情報・写真・アルバムデータは使えません。

## 架空の園児データ同期テスト
- iPhoneの `/pair` 画面で6桁コードを入力してペアリングします。
- 「次のテスト園児に切り替える」を押すと、架空の固定データ「テスト園児A→B→C」を順に切り替えます。
- MacBookやWindowsの `http://localhost:4318/demo-child` を更新すると、同じ架空の名前が表示されます。
- ブラウザの画面表示は3秒ごとに取得します。自由入力や実在園児データの送信・保存は実装していません。

## HTTPS起動の準備（任意・開発者向け）
標準の `node sync-server/server.js` は引き続き**HTTP（暗号化なし）テスト専用**です。
信頼できるLAN内でのみ、架空のテストデータを使ってください。

Node.jsのHTTPSモードは、認証局が署名した**対象IPアドレス用の証明書**と秘密鍵の両方がある場合だけ起動します。macOS / Windows とも環境変数で指定できます。

macOS（実際のパスに読み替え）:
```sh
OMOIDE_TLS_CERT=/path/to/your/cert.pem OMOIDE_TLS_KEY=/path/to/your/key.pem node sync-server/server.js
```

Windows PowerShell（実際のパスに読み替え）:
```powershell
$env:OMOIDE_TLS_CERT="C:\\path\\to\\cert.pem"
$env:OMOIDE_TLS_KEY="C:\\path\\to\\key.pem"
node sync-server/server.js
```

HTTPSモード時は `https://<パソコンのIP>:4318/pair` にアクセスしてください。iPhoneにも発行元の信頼設定が必要です。**ブラウザの証明書警告を無視して進む運用はしないでください。** 秘密鍵はGitHubへコミットしないでください。

> HTTPS対応はサーバーの土台だけです。端末認証の永続化、端末の取り消し、保護された写真保存、編集競合の処理、バックアップや自動同期は未実装です。園児の写真など実データを使う前に追加の安全設計とテストが必要です。

## MacBook NeoでのHTTPS接続テスト（mkcert）

今のHTTPテストはそのまま残ります。HTTPSは**テスト用の架空データのみ**使用します。証明書をMacBookに生成し、iPhoneでも信頼させる手順が必要です。

1. MacBookでHomebrewがあるか確認： `brew --version`
2. Homebrewがある場合、 `brew install mkcert` 、続いて `mkcert -install`
3. `mkdir -p sync-server/certs`
4. MacBookのローカルIPアドレスを確認： `ipconfig getifaddr en0`
5. **実際のIPアドレスに置き換えて**証明書を生成：

```sh
mkcert -cert-file sync-server/certs/cert.pem -key-file sync-server/certs/key.pem localhost 127.0.0.1 192.168.0.8
```

6. すでに起動中の4318番サーバーは Control+C で停止してから、以下でHTTPS起動：

```sh
OMOIDE_TLS_CERT=sync-server/certs/cert.pem OMOIDE_TLS_KEY=sync-server/certs/key.pem node sync-server/server.js
```

7. MacBookで `https://localhost:4318/security-status` を開き、 `"encrypted":true` を確認する。
8. iPhoneから `https://192.168.0.8:4318/security-status` にアクセスするには、 `mkcert -CAROOT` で表示したディレクトリの **rootCA.pem（公開CA証明書）だけ** をiPhoneにAirDropして、iPhoneの設定でプロファイルをインストールし、証明書の信頼設定で有効にする必要があります。作業後は端末の管理方針に従って不要なテスト用CAを取り除いてください。
9. **rootCA-key.pem、sync-server/certs/key.pem は絶対に共有・GitHub登録しないこと。** 証明書の警告を無視して進まないこと。証明書を信頼させる操作は、個人所有のテスト端末だけに限定すること。

この方法は開発中のローカル認証局による暗号化テスト用です。園の本番端末や園児の写真を扱うための運用・監査・端末権限は別途設計します。

## 端末認証テスト（第4段階）
- ペアリング後に `/pair` 画面に「この端末の接続を解除」ボタンが表示されます。押すと、そのブラウザの登録セッションを無効化します。
- iPhoneのSafariから `https://<MacBookのIP>:4318/pair-status` を開くと、`paired: true/false`、セッション有効期限、匿名デバイスIDを確認できます。
- サーバーを動かすMacBook/Windows **自身からのみ** `https://localhost:4318/devices` を開いて、一時的に登録された端末の数を確認できます。
- `/revoke-all` にはローカルからのPOSTによる全端末解除APIを用意しています（通常のブラウザ画面のボタンは未実装）。
- HTTPSモードでは登録情報（ランダムな認証トークンのSHA-256ハッシュと有効期限）をローカルの `sync-server/data/pairing-sessions.json` に保存し、再起動後も最大7日間有効です。HTTPモードはメモリ保存のみで1時間有効、再起動時に消えます。端末固有のOS識別ではありません。
- ブラウザ側の通常POSTにもOrigin確認を追加しました。HTTPのテスト運用は依然として安全な本番用途には使えません。
- **既存の写真・園児情報・アルバムアプリのデータには接続していません。実データ送信は禁止です。**

## 再起動後の端末登録引き継ぎ（HTTPSテストのみ）
- HTTPSサーバーを再起動しても、同じアドレス・証明書で接続すればiPhoneのペアリング状態を最大7日間維持します。
- 保存場所は `sync-server/data/pairing-sessions.json`（Gitで無視されます）。平文の認証トークンは保存せず、SHA-256ハッシュ・匿名ID・登録時刻・期限のみ保存します。サーバー起動中の変更はファイルに反映されます。
- MacBookで `https://localhost:4318/devices` にアクセスすると登録端末数と期限、`storedOnDisk:true` を確認できます。
- iPhoneで「この端末の接続を解除」を押すと登録ファイルからも解除され、再起動しても無効のままです。全端末解除APIも保存に反映されます。
- 証明書やIPアドレス、SafariのCookieを変更すると、再度ペアリングが必要になる場合があります。**端末登録ファイルや証明書の秘密鍵を他人に渡さないでください。**
- これはテスト用の認証保存で、本番の園児データを送受信する仕組みではありません。盗難端末の管理、ユーザー認証、証明書更新、操作ログ、監査などは未実装です。

## 第5段階：架空のテスト画像転送

- HTTPSサーバーを起動し、ペアリング済みのiPhoneのSafariで `https://<MacBookのIP>:4318/pair` を開きます。
- 「📸 テスト画像の送信」に表示された**固定イラスト**を確認し、「このテスト画像をMacBookへ送る」をタップします。
- 成功したら、MacBookのSafariで `https://localhost:4318/demo-image/view` を開き、イラストが表示されることを確認します。
- 保存状態のJSONを見たい場合は `https://localhost:4318/demo-image/status` を開きます。
- 送信された画像はMacBookの `sync-server/data/synthetic-demo-image.svg` に保存されます。このディレクトリはGitHubへアップロードされないよう除外済みです。
- **iPhoneの写真ライブラリやアルバムアプリには触れません。** 固定の内蔵テスト画像とバイト単位で完全一致するデータ以外はサーバーで拒否します（本人の写真を選択するUI自体がありません）。
- 画像転送はHTTPSが必須です。未ペアリングの端末からの送信・閲覧は拒否します（サーバー自身のループバック閲覧を除く）。
- これは暗号化されたテスト画像転送であり、実際の写真同期、複数写真の保存、双方向同期、バックアップではありません。

開発者向けの内蔵画像検証テスト：

```sh
node --test sync-server/demo-image.test.js
```

## 第6段階：テスト画像5枚の一括送信・重複防止・再送

1. HTTPSサーバーを起動して、iPhoneで `https://<パソコンのIP>:4318/pair` を開きます。ペアリング済みなら再登録不要です。
2. 「📚 テスト画像5枚をまとめて同期」→「テスト画像5枚を送信」をタップします。
3. iPhoneに「新しく保存5枚／重複をスキップ0枚」のように表示されます。
4. MacBookのSafariで `https://localhost:4318/demo-batch/list` を開き、5件とも `received:true` かを確認します。
5. 各画像は `https://localhost:4318/demo-batch/view/flower` などから閲覧できます。
6. iPhoneで同じボタンをもう一度押すと、すでに保存された画像は重複保存せず、スキップ数が増えます。通信が途中で止まった場合も同じボタンで再送できます。

保存先： `sync-server/data/demo-batch/`。テスト用に生成した固定イラスト5件だけで、実際の写真・園児名・アルバムには触れません。HTTPSとペアリングが必要です。

開発者テスト：

```sh
node --test sync-server/demo-batch.test.js
```

注意：この段階の再送はボタンを再度押す方式で、Safariのバックグラウンド自動再送ではありません。写真ライブラリとの連携・本番の写真自動同期は未実装です。

## 第7段階：通信中断・再送シミュレーション

以前のテストで5枚が保存済みの場合、まずMacBook自身のSafariで `https://localhost:4318/demo-batch/admin` を開き「テスト画像5枚をリセット」を押します。これは**固定テスト画像5枚だけ**を消す操作で、園児写真や既存アプリのデータには影響しません。

1. iPhoneで `https://<MacBookのIP>:4318/pair` を開く。
2. 「2枚で中断するテスト」を押す。プログレスバーが2/5になり、残り3枚と表示される。
3. MacBookで `https://localhost:4318/demo-batch/list` を開いて、2件のみ `received:true` を確認。
4. iPhoneで「テスト画像5枚を送信・再送」を押す。すでに保存されている2枚は再送せず、残り3枚だけを送る。
5. 同じ一覧で5件すべて `received:true` になれば成功。

これは**操作上の中断を再現したテスト**です。物理的なWi-Fi切断やSafariの終了、通信中の障害を完全に再現したテストではありません。自動バックグラウンド再送や実際の園児写真の同期も未実装です。

開発者テスト：`node --test sync-server/demo-batch.test.js`

## 第8段階：Wi-Fi復帰時の自動再送（固定テスト画像のみ）

1. MacBook側の `https://localhost:4318/demo-batch/admin` で固定テスト画像5枚をリセット。
2. iPhoneの `https://<パソコンIP>:4318/pair` で「2枚で中断するテスト」を押して2枚保存した状態にする。
3. 「Wi-Fi復帰時に未送信分を自動再送（テスト用）」をオンにする。
4. Safariが表示され通信できる間、5秒ごとにサーバーの保存済み一覧を確認し、未保存の残り3枚だけを自動送信する。
5. MacBookの `https://localhost:4318/demo-batch/list` を再読み込みし、5枚とも `received:true` になったことを確認。
6. 完了すると自動再送はオフになる。途中でネット接続が切れた場合は、復帰後に再試行する（iOSがSafariの実行を一時停止した場合は次回表示時に再試行）。

**制限**：チェックボックスをオンにしたときだけ動作し、Safariを完全終了している間のバックグラウンド同期は未実装。ページ再読み込み後に監視を再開するには再度オンにする必要がある。通信中断を模擬した再送テストであり、本番のネットワーク障害・大容量写真・OSバックグラウンド処理はまだ未検証。送信できるのは固定された5枚の架空SVGのみ。

## 第9段階：おもいでブック本体から同期状況を確認

開発ブランチのおもいでブックで「設定」→「🔄 同期状況（準備中）」を開き、HTTPS同期サーバーのアドレス（例：`https://192.168.0.8:4318`）を入力して「接続・ペアリング状況を開く」を押します。同じ端末の別タブで `/sync-status` が開きます。

同期サーバーの状態画面は、HTTPS通信、**そのタブを表示している端末のペアリング状態**、固定テスト画像の受信枚数（最大5枚）だけを表示します。「実際の写真・アルバム：未同期（未実装）」は固定表示で、誤解を避けています。

この機能は外部URLへのナビゲーションであり、**おもいでブック本体は同期サーバーと直接通信せず、園児情報・画像・アルバム・認証トークンを送信しません**。接続先のHTTPS URLだけを当該端末のlocalStorageに保存します。サーバーIPが変わったら入力を更新してください。

注意：MacBookの `https://localhost:4318/sync-status` ではMacBookブラウザの接続状態、iPhoneからアクセスした `https://192.168.0.8:4318/sync-status` ではiPhoneブラウザの接続状態が表示されます。それぞれ異なります。

## 第10段階：アプリ内のサーバー通信状態

開発ブランチの「設定 → 🔄 同期状況」で同期サーバーのHTTPS URLを入力すると、アプリ内の「📱 同期サーバーとの通信」に結果が出ます。「通信状態を再確認」から手動で更新可能です。

- 🟢 は **読み取り専用 `GET /health` にHTTPSで応答が返った**ことのみを示します。端末のペアリング、写真転送、バックアップ、アルバムの同期完了を意味しません。
- ⚪ の場合、同期サーバー停止・別ネットワーク・証明書・ブラウザのローカルネットワーク通信制限・CORSなどの可能性があります。必ずしもサーバーが停止したとは限りません。
- `/health` のCORS読み取りは開発中のアプリURLとローカルポート3000に限定します。写真、園児、アルバム、CookieをGETに含めません。
- ブラウザからの接続確認は開発・テスト限定です。実際の園児データは送信しません。

## 第11段階：アプリ内のペアリング状態確認

開発ブランチのおもいでブックの「設定 → 🔄 同期状況 → 🔐 この端末のペアリングを確認」を押すと、同期サーバーの同一オリジンに小さな確認画面を開きます。

- 確認画面は同期サーバーに保存済みのHttpOnly Cookieを使って `GET /pair-status` を読み、ペアリング済みか否か**だけ**を元のアプリに通知します。
- アプリ側では通知元URL、確認画面のウィンドウ、使い捨てランダム確認番号がすべて一致した場合だけ結果を表示します。認証トークン、園児情報、写真やアルバムは通知しません。
- 同期サーバーを開くブラウザのCookieが必要です。接続先URL（IPアドレスかlocalhost）が以前のペアリングと違う場合は再登録が必要になります。
- Safariで確認画面が閉じない、または結果が来ない場合はその画面を確認してください。ブラウザが別ウィンドウの通信を制限している場合もあるため、その際は従来の「接続・ペアリング状況を開く」で確認できます。
- 接続先アドレスを変更するとペアリング状態は「未確認」に戻ります。
- 実際の写真やアルバムの自動同期は未実装です。これらのデータは変更・送信しません。

## 第12段階：架空アルバムの双方向同期・競合防止

1. MacBookとiPhoneの両方でおもいでブックの「設定 → 同期状況」から「📚 架空アルバムの双方向同期テストを開く」を選ぶ。同期サーバーの `https://<IP>:4318/fictional-album` を直接開いてもよい。
2. どちらも同期サーバーにペアリングされている必要がある。URLは両端末で同じホスト（例：`192.168.0.8`）を使う。localhostとIPは別々のCookieになる。
3. iPhoneでタイトル・メッセージ・背景色を変更し「サーバーに保存」を押す。MacBook側は約4秒以内に新しい内容に更新される。
4. MacBookで別の選択肢に変更して保存すると、iPhone側も同様に更新される。
5. 競合テスト：双方で同じ改訂番号を開き、両方で別の値を選んでから、片方を先に保存し、もう片方で保存を押す。後から保存する側は HTTP 409 の競合メッセージになり、**編集内容は失われず、サーバーの新しい保存内容も上書きしない**。
6. 「サーバーの最新版を読み込む」は編集中の内容を破棄する場合に確認ダイアログを出す。サーバーの状態は `sync-server/data/fictional-album-sync.json` に保存し、同期サーバー再起動後も残る。

**個人情報保護のため、自由入力欄はありません。** アルバムのタイトル・メッセージ・背景色はいずれも固定された架空の選択肢のみで、写真・園児名・本物のアルバムを送ることはできません。入力キーの追加や自由文の送信は拒否します。

これはHTTPSの同期サーバー上での架空データの双方向編集テストであり、おもいでブックの実際のアルバムとの自動同期は未実装です。Safariがバックグラウンドで停止すると、自動更新も停止することがあります。

開発者テスト：`node --test sync-server/fictional-album.test.js`
