# 第11段階 Safari検証後のアイコン選択・再ログイン修正

基準コミット：`2b1f67302a2dca031ed05c94fbe3ed9f32b6e2c6`。
対象入口：`stage9-entry.html?registration=1`。2026年度・架空データ専用・本番利用不可。

## 確認できた点／未確認の点

- 写真入力は32×32の単色画像をDataTransfer経由でFile入力へ渡すだけで、選択UIがなかった。これはテスト用の顔アイコンを選ぶ要件を満たさず、ブラウザのFile入力書換え・FileReader・リサイズ処理にも依存していた。SafariでこのAPI依存が直接の失敗原因だったとは断定しない。
- 第9段階DBの選択時読み込みが失敗すると、子のmodeがloadingのままボタンだけ有効になり、再送信しても無視する経路があった。HTML required検証も含め、保存状態の再確認を実行できるようにした。
- 入口は親iframeの汎用loadイベントだけで準備完了にしていた。準備前の操作が無視され、その後子側が待機したままになる経路もあった。現在文書のnonceを持つ準備応答を待ち、子はその応答を送るまで操作を無効化する。
- マップ失敗後に入口を作り直すと、そのload完了で失敗表示を隠していた。再生成が完了してからMAP_LOADを表示する。
- Safari固有のIndexedDB・Web Crypto・鍵／anchor不一致は再現・特定できていない。暗号方式・パラメータ・形式・anchor計算・DB名・保存キーは変更しない。

## アイコン選択

Ver.6原本・CSS・背景・花キャラクターは未変更。写真欄を押した時だけ、既存のdialog/overlayスタイルを使う小さなテストアイコン選択を追加する。
6種類の架空の顔をPNGとしてメモリ内に生成し、選択したPNGを既存のimageDataと丸枠プレビューに直接設定する。キャンセル時は元のアイコンを保持する。
File入力のclick/change/dropは捕捉し、写真ライブラリを開かない。新しい選択経路はDataTransfer・File・FileReader・Imageのリサイズに依存しない。
保存は従来の登録ボタンと「保存してマップへ」。既存のPNG/JPEGは変更せず読める。新しいPNGへの変更は利用者が選択・登録・保存した時だけ。顔写真フィールド以外のID・氏名・表示名・未知項目は従来の保持処理を使用する。

## 準備応答と失敗段階

入口はsandbox内の新しい文書がloadした後の `stage9-entry-ready` を、送信元・null origin・現在のnonce・許可フィールドで検証する。古いloadイベントや古い文書のnonceでは進めない。
マップも既存channel/session/source検査を通る `fj-demo-document-ready` を待つ。sandboxは緩めない。マップ原本・花びら・ズームの実装は変更しない。
ログアウトでは従来通り登録鍵・復号済み参照を閉じ、セッションとsrcdocを破棄する。新しい文書とセッションを作ってから再解錠する。

画面に表示するコードは次の通り。秘密情報・個人データ・例外の生テキストはログ出力しない。

| コード | 分かる段階 |
| --- | --- |
| ENTRY_READY | 入口の現在文書の準備が未確認。DB解錠前 |
| LOGIN_READ | 第9段階ログインDBの読取／対象・形式確認失敗。再確認ボタンで再試行可能 |
| LOGIN_UNLOCK | ログイン用暗号文の解除失敗。誤パスフレーズと改ざん等は区別できない |
| LOGIN_CREATE / RECOVERY_CONFIRM | 初回設定保存／復旧キー確認の失敗 |
| REG_KEY | ログイン成功後の登録用鍵の準備失敗 |
| REG_READ | 第10段階登録DBの読取・scope／anchor／形式確認失敗。このAPIでは詳細原因を区別できない |
| REG_OPEN | 登録用暗号文の復号・レコード照合失敗 |
| REG_RESTORE | 登録復元のその他の失敗 |
| MAP_LOAD | ログイン・登録復元後のマップ準備失敗。入口再生成後も表示を維持 |

読み込み失敗の再試行で初期化・削除・暗号文再生成・自動上書きをしない。LOGIN_READ以外は同じクラスでパスフレーズを再入力して試せる。MAP_LOADは入口の再生成後に再選択・再解錠する。

## Safari実機での確認

変更を配置した同じHTTPS origin（またはlocalhost）の通常タブで行う。サイトデータを消さず、既存クラスとパスフレーズを使う。

1. 入口から解除する。元の登録内容と旧JPEGアイコンがそのまま復元されることを確認する。
2. Ver.6で写真欄を押し、6種類のテストアイコンが表示され、写真ライブラリが開かないことを確認する。いったんキャンセルし、元の画像が残ることを確認する。
3. 別のアイコンを選び、丸枠プレビュー→登録／変更を反映→「保存してマップへ」。おもいでキャッチで同じ画像を確認する。
4. ログアウト→同クラス・同パスフレーズで解除を3回行う。再読み込み後にも再解錠し、アイコンと登録内容を確認する。
5. 誤入力後に正しいパスフレーズで再試行する。失敗した場合は画面のコードと、入口／登録復元／マップのどの段階かを確認する。パスフレーズ・復旧キー・園児データを送る必要はない。
6. 読取失敗は「保存状態を再確認」、マップ失敗は「もう一度読み込む」を使う。消去・初期化はしない。別URL・通常／プライベートタブ・originの違いも確認する。

既存クラスなのに初回設定と表示された場合は、新規設定やサイトデータ消去で直そうとせず、保存した時と同じorigin・ブラウザ・タブ種別かを確認する。

この環境にWebKitは未インストールで、Safari実機は未検証。Chromiumの反復検証や障害注入の合格だけでSafari固有の原因解消とは扱わない。
