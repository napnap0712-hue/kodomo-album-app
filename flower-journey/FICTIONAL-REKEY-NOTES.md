# 第6段階：架空名簿のパスフレーズ変更・復旧再設定

基準コミット: `2524d81006572f7d45721ac75289de9768051f07`。
既存の第5段階コード、v1暗号化形式、既存画面、保存処理は変更しない。第5段階文書の未実装項目のうち、鍵ラップ更新を独立モジュールとして追加する。

## API

`FlowerFictionalRosterRekey.createDemoRekey(boundary, session, scope)` は、信頼できる親の有効な同一クラス・年度のdemoセッションにだけ結び付く。

- `changePassphrase(envelopeJSON, oldPassphrase, newPassphrase)`
- `resetWithRecoveryKey(envelopeJSON, recoveryKey, newPassphrase)`

どちらも成功時だけ `{envelopeJSON}` を返す。新しい暗号化JSON候補を生成するだけで、元文字列・元パッケージ・保存先は変更しない。「現在のデータ」を選択・保存する機能はない。
新しいパスフレーズは第5段階と同じ16文字以上の規則を使い、現在と同じパスフレーズへの変更・再設定を拒否する。復旧時も候補が現在のパスフレーズでないことを検査する。

## 形式との整合性

更新前に第5段階エンジンで旧パッケージ全体を認証・復号・レコード検証する。構造検証だけを成功扱いにしない。
一時的に抽出可能なDEKとして解除し、新しいsaltとパスフレーズ由来KEKでDEKを包み直す。

変更するのは次の情報だけ。

- `kdf.salt`（方式・反復回数はPBKDF2-SHA-256／600,000回のまま）
- `wrappedKeys.passphrase` のIV・暗号文
- `auth` のIV・全体認証タグ

`data.iv`・`data.ciphertext`、`wrappedKeys.recovery`、形式バージョン、クラス・年度・基準年度、既存保存キー、暗号方式は変えない。
名簿本体を暗号化する呼び出しは行わず、DEKによるAES-GCM encryptは全体認証用の空メッセージだけ。
新しい候補は、既存の第5段階エンジンで新パスフレーズによる完全な復号を確認してから返す。復旧再設定時は既知の復旧キーによる復号も再確認する。
パスフレーズ変更経路には復旧キーの入力がないため、その鍵の正しさを新たに確認することはできないが、元の復旧ラップを完全に維持する。

この安全な組合せのため、旧パスフレーズ経路では同じ旧秘密からの鍵導出を複数回行う。最適化は暗号API境界のレビュー後に別途検討する。

## IVと失敗時の取扱い

同じDEKで全体認証を複数回行うため、IVを使い回してはいけない。

- `crypto.getRandomValues` で新しいsaltと12バイトIVを生成する。
- DEKのSHA-256フィンガープリントで識別する非公開のメモリ内台帳を、同じJS realmの全サービスインスタンスで共有する。
- 入力内の既知のIV・saltと、同じ台帳内で予約した全IV・saltとの重複を避ける。失敗した更新の予約も再利用しない。
- 同時更新、古いコピーからの分岐更新でも、同じrealm内では予約を共有する。乱数衝突を16回避けられなければ停止する。
- フィンガープリント作成時の平文DEKバイト列は一時利用だけで、finallyで可能な範囲の上書きを行う。台帳に平文鍵・パスフレーズ・名簿は保持しない。

台帳は永続化しない。別プロセス・別端末・再起動をまたいだ全履歴の突合はできず、その場合の重複回避はCSPRNGの確率的な一意性に依存する。本番運用には永続的な世代・IV管理、更新回数上限、競合制御の設計と独立レビューが必要。

途中失敗時は候補や秘密情報を返さず、元パッケージは旧パスフレーズ・復旧キーで引き続き使える。再試行時も新しい乱数を使う。入力を上書きしたり、保存領域へ巻き戻したりする処理はない。
各非同期処理の前後でセッションを検査し、失効後の遅い結果を返さない。JS文字列やCryptoKey、OSメモリの完全な消去は保証しない。

## 制約と次段階

- 古い暗号化コピーは、旧パスフレーズで解除できる。新候補を生成しても過去のコピーや他端末のコピーを失効できない。
- 古い認証済みコピーへの巻き戻しを、この形式やメモリ内台帳だけでは防止できない。現在版の管理は未実装。
- 保存、トランザクション、クラッシュ回復、NASの競合制御、端末間の取消しは未実装。暗号化JSON候補の生成成功と保存完了を混同しない。
- 復旧キーそのものの変更、過去パスフレーズの再使用禁止、正式認証は未実装。
- 新旧パスフレーズ、復旧キー、平文DEKをログに出さない。テストの固定文字列は架空のテスト用だけで、生成した復旧キーは出力しない。
- UIにも1234のデモログインにも接続しない。実データ取得、localStorage、IndexedDB、外部通信を追加しない。
- Safari・Windows実機の待ち時間や中断復帰、暗号設計の独立レビューを行うまで実データに適用しない。
